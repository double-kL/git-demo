## 🐛 常见问题和解决方案

### 问题1：后端未启动

**症状：**
- 控制台显示 `net::ERR_CONNECTION_REFUSED`
- 无法访问 http://localhost:8000/api/health

**解决：**
```bash
# 启动Mock后端
双击 start-mock-server.bat
```

---

### 问题2：Token验证失败（已修复）

**症状：**
- 登录成功但访问动态时显示"未登录"
- 控制台显示 401 错误

**原因：**
- Mock后端的Token验证逻辑有bug

**解决：**
- ✅ 我已经修复了这个问题
- ⚠️ **必须重启Mock后端才能生效**

**修复内容：**
```javascript
// 之前的代码（有bug）
const userId = tokenValue.split('_')[2]; // 错误：userId可能包含"u"和数字

// 修复后的代码
let tokenStore = {}; // 存储token和userId的映射
tokenStore[token] = userId; // 保存映射关系
const userId = tokenStore[tokenValue]; // 准确获取userId
```

---

### 问题3：端口被占用

**症状：**
- 启动后端时显示 `EADDRINUSE: address already in use`

**解决：**
1. 找到占用8000端口的程序并关闭
2. 或修改端口（见下方）

**修改端口方法：**
编辑 `mock-server.js` 第9行：
```javascript
const PORT = 8001; // 改为其他端口
```

同时修改 `app.js` 第6行：
```javascript
apiBaseUrl: 'http://localhost:8001', // 改为相同端口
```

---

### 问题4：CORS跨域错误

**症状：**
- 控制台显示 `CORS policy: No 'Access-Control-Allow-Origin'`

**原因：**
- 后端未启动，或前端直接用 `file://` 协议打开

**解决：**
- 确保后端已启动
- 或使用 `start.bat` 启动前端服务器

---

### 问题5：旧Token导致问题

**症状：**
- 重启后端后，之前的登录失效

**原因：**
- 后端重启后tokenStore被清空
- 浏览器中还保存着旧Token

**解决：**
```javascript
// 在控制台执行
localStorage.clear()
location.reload()
```

```
1. 前端发送: Authorization: Bearer <token>
2. 后端接收: 提取Bearer后的token
3. 后端查找: 在tokenStore中查找userId
4. 后端验证: 在users中查找用户
5. 验证通过: 返回数据
```

如果中间任何一步失败，就会返回401错误。
