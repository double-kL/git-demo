# Mock后端服务器使用说明

## 🎯 简介

这是一个用于测试 DiffProtect Pro 前端的 Mock 后端服务器，使用 Node.js + Express 实现，完全模拟真实后端的所有API接口。

## 📋 前置要求

- **Node.js** (推荐 v14 或更高版本)
- 下载地址：https://nodejs.org/

## 🚀 快速启动

### Windows 系统

1. **双击运行启动脚本**
   ```
   双击 start-mock-server.bat
   ```

2. 或者手动运行：
   ```bash
   # 首次运行需要安装依赖
   npm install
   
   # 启动服务器
   npm start
   ```

### Mac/Linux 系统

1. **给脚本添加执行权限**
   ```bash
   chmod +x start-mock-server.sh
   ```

2. **运行脚本**
   ```bash
   ./start-mock-server.sh
   ```

3. 或者手动运行：
   ```bash
   # 首次运行需要安装依赖
   npm install
   
   # 启动服务器
   npm start
   ```

## 📝 功能说明

### 1. 人脸验证 (无需登录)

- **接口**: `POST /api/verify`
- **功能**: 模拟4个FR模型的人脸验证
- **返回**: 每个模型的相似度、判定结果和综合结论
- **特点**: 返回固定的模拟数据，便于测试UI展示

### 2. 用户注册

- **接口**: `POST /api/auth/register`
- **功能**: 创建新用户
- **校验**: 
  - 手机号11位
  - 昵称2-20字符
  - 密码6位以上
  - 手机号和昵称不能重复
- **返回**: 用户信息和Token

### 3. 用户登录

- **接口**: `POST /api/auth/login`
- **功能**: 验证用户凭据
- **返回**: 用户信息和Token
- **测试账号**: 13800138000 / 123456

### 4. 获取动态列表 (需登录)

- **接口**: `GET /api/posts`
- **功能**: 分页获取所有帖子
- **参数**: 
  - `page`: 页码 (默认1)
  - `page_size`: 每页数量 (默认10，最大20)
- **返回**: 帖子列表，包含点赞状态
- **初始数据**: 启动时会创建2条测试动态

### 5. 发布动态 (需登录)

- **接口**: `POST /api/posts`
- **功能**: 发布新帖子
- **支持**: 
  - 文字内容
  - 图片上传 (最多9张)
  - 视频上传
  - 保护选项
- **文件存储**: 上传的文件保存在 `uploads/` 目录

### 6. 点赞 (需登录)

- **接口**: `POST /api/posts/:postId/like`
- **功能**: 点赞/取消点赞 (toggle)
- **返回**: 点赞状态和点赞数

### 7. 获取/保存设置 (需登录)

- **接口**: 
  - `GET /api/settings` - 获取设置
  - `PUT /api/settings` - 保存设置
- **功能**: 管理用户的默认保护参数
- **数据**: 保存在内存中，重启后重置

## 🔐 认证机制

- **Token格式**: `Bearer mock_token_<userId>_<timestamp>`
- **验证**: 所有需要登录的接口都会验证Token
- **过期**: Mock服务器中Token不会过期

## 🐛 故障排查

### 问题1: 服务器启动失败

**错误**: `Error: Cannot find module 'express'`

**解决**:
```bash
# 重新安装依赖
npm install
```

### 问题2: 端口被占用

**错误**: `Error: listen EADDRINUSE: address already in use :::8000`

**解决**:
1. 找到占用8000端口的程序并关闭
2. 或修改 `mock-server.js` 第9行的端口号

### 问题3: 前端无法连接后端

**现象**: 点击按钮没反应，控制台显示网络错误

**检查**:
1. Mock后端是否启动 (访问 http://localhost:8000/api/health)
2. 前端配置的地址是否正确 (app.js 第6行)
3. 浏览器控制台是否有CORS错误

### 问题4: 图片上传失败

**检查**:
1. `uploads/` 目录是否存在且有写入权限
2. 文件大小是否合理 (<10MB)
3. 后端控制台是否有错误信息
